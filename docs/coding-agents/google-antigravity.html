Google Antigravity capability guide

Everything the agy CLI reads, writes, and resolves — the split roots that surprise everyone, one workspace root spelled four ways, a global skill path that is narrowed rather than settled, workflows that provably exist at a path nobody has published, and the richest and least-known part of the product: the skills.json declared-source schema. Antigravity is closed source. But the shipped executable embeds a complete first-party customization manual, so this page is anchored to installed agy — 1.1.11 (169 MB) at the first pass, re-verified 2026-08-13 against the 1.1.12 build (172 MB) that replaced it on disk — and to that manual; where the manual and the public docs pages disagree, the manual governs and both sides are stated. No positive claim comes from memory or a web search; stated negatives name their method — including the 2026-08-13 site-scoped searches — and the two off-domain codelab leads are graded I, not D.

Closed source is not the same as opaque, and this is the clearest example of the difference. The official Antigravity CLI repository publishes documentation, examples, and a changelog — not the application source. There is no tag to pin, no loader to read. What the product ships instead is better than most open repositories offer for this purpose: the installed executable carries a complete first-party customization manual inside it, and extracts the same text to disk as a built-in skill.

That manual is the agy-customizations builtin skill — a SKILL.md plus docs/rules.md, docs/skills.md, docs/plugins.md, docs/hooks.md, docs/mcp_servers.md and docs/json_configs.md. It lives at ~/.gemini/antigravity-cli/builtin/skills/agy-customizations/, and the same document is recoverable from the executable itself. S

Why that outranks the website. The embedded manual is version-pinned to the build it shipped with, in a way no rolling documentation page can be. antigravity.google exposes no per-page revision date; the manual inside agy 1.1.11 is, by construction, what 1.1.11 believes about itself. Where the two disagree, this page follows the manual and the binary, says so, and keeps both sides on the record rather than silently normalizing one away.

Rule files carry a 12,000-character limit. D

Rules support an @file reference mechanism — D/S. "You can reference other files using @filename in a Rules file." A relative path resolves from the rule file's own location; an absolute @/path is tried as a true absolute path first and, if missing, workspace-relative. Documented on both the rules-workflows and IDE rules pages (retrieved 2026-08-13), and implemented in the shipped binary — resolveFileIncludes error strings and the customizations.(*Manager).parseAtMentions symbol, verified on agy 1.1.12. The public docs conflate global rules with the global instructions file — D. Do not scan for it as a supported contract, and do not parse it if you find one.
