OpenAI Codex capability guide

Everything the OpenAI Codex CLI reads, writes, and resolves — scopes, capability types, the numeric config-layer precedence, the root → cwd instruction walk, the inverted plugin-manifest probe, and the bounded unknowns. Verified against the pinned rust-v0.147.0 source and the installed codex-cli 0.147.0 package, not against vendor prose: where a rolling documentation page and the shipped build disagree, the build governs this version row and both sides are stated.

echo overview

The unit of analysis is the coding agent’s command-line executable plus the files and state that executable directly reads, writes, installs, or manages. CLI-native plugins, marketplaces, TUI features, remote-control entry points, cloud task submission, and service-backed memory are in scope. IDE extensions, desktop applications, and web-only surfaces are out of scope even when they share a product name or an artifact path.

Every claim on this page carries an evidence class and a citation. Nothing here is added from memory or from a web search: if the source analysis does not state it, it is not on this page, and where the analysis records an unknown it is reproduced as an unknown with its U- number.

The six things most often gotten wrong, each corrected against the pinned source or the installed build and expanded further down:

The direction of travel is the single most-misunderstood part of Codex. Codex searches upward to locate the project root, and then orders the instructions it found downward, root → cwd. Closest content appears later. The project root is a hard ceiling, not a starting point. A "walk up from cwd, nearest wins" reading produces exactly the reverse order. D/S · AGENTS.md guide · tagged loader

Verified two ways — S. The instruction resolver's own module header states the algorithm in three numbered steps: determine the project root by walking upwards from cwd until a project_root_markers entry is found; collect every AGENTS.md from the project root down to cwd (inclusive); and "we do not walk past the project root". The implementation builds the directory list cwd-upward, breaks on cursor == root, then calls dirs.reverse() — upward search, downward order. Independently, the config loader carries the assertion message "project layers are not ordered from root to cwd", a literal recoverable from the installed binary, confirming the same invariant for the config stack.

The global slot is a separate mechanism — D/S, confirmed at source strength. Global instruction lookup is exactly $CODEX_HOME/AGENTS.override.md, then $CODEX_HOME/AGENTS.md. It is a two-element loop over [LOCAL_AGENTS_MD_FILENAME, DEFAULT_AGENTS_MD_FILENAME] joined to codex_home, living in codex-home/src/instructions/mod.rs — a crate that re-declares its own private constants and never reads Config. That is why two things are true and not merely asserted:

  • project_doc_fallback_filenames cannot reach it — configurable fallback filenames are project-only.
  • No byte budget applies there. The file is read whole and trimmed; the module contains no max_bytes and no truncate.

A distinct error string, "Failed to read global AGENTS.md instructions from", confirms the global read is a separate operation from the project walk. ~/.codex/AGENTS.md is therefore a global prefix, not an ancestor that a project override can replace. S

Override locality is structural, not a rule — S. Each directory is probed in its own async closure, so the return on the first hit exits that directory only and cannot suppress another. An AGENTS.override.md at the repository root replaces the root's own AGENTS.md and nothing else; a nested directory's files are unaffected.

The budget — D/S. Selected project files concatenate into initial context up to project_doc_max_bytes, whose default is the literal DEFAULT_PROJECT_DOC_MAX_BYTES = 32 * 1024 (32 KiB). The budget is shared across the whole ordered list — a remaining counter — and truncation emits "project doc exceeds remaining budget; truncating", a literal also present in the installed binary. That budget does not cap the separate global prefix. The installed package independently carries the first-party sentence "respecting normal project-document precedence (AGENTS.override.md, AGENTS.md, then configured fallback filenames)".

A shared budget means order decides who gets truncated. Because the chain is emitted root → cwd and the counter drains as it goes, it is the closest file — the one a reader most expects to be authoritative — that is truncated first when 32 KiB runs out.
